## First-capability decision

No single candidate is justified as the first AI implementation. Symptom analysis is the most visible candidate because the existing frontend once contained a shaped symptom-entry interaction, but that UI was explicitly a deterministic demonstration and Phase 10 converted it to a deferred state. It does not define a target, labeled dataset, clinical operating point, or safe ML task.

Selecting symptom analysis merely because it has the most visible UI would still invent requirements. Disease prediction, report analysis, medicine information, and interaction detection require even more missing data or authoritative knowledge sources. Health recommendations require a clinician-reviewed policy and consent model. Chatbot/RAG is explicitly deferred by earlier architecture.

**Final Phase 13 outcome:** `BLOCKED`. The project must not enter model implementation until the owner approves one capability, its exact problem definition, target/output, minimum feature schema, dataset/corpus, algorithm or retrieval approach, safety policy, and evaluation plan.
